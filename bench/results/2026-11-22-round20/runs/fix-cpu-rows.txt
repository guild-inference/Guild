## switches

- GUILD_KQ_ROWS512, default 1: Q4_K gate/up and Q4_K / Q6_K down expert rows on kq_rows512; 0 restores the library's rows.
- GUILD_IQ4NL_PF, default 6: IQ4_NL down rows prefetch 6 rows ahead (0-64 accepted); 2 restores the old distance.
- GUILD_POOL_IQ4XS, default 1: IQ4_XS gate/up rows on iq4xs_rows512; 0 restores the library's rows.
- GUILD_POOL_ACK, default 0 since aa12065 (read when the pool is made): unset or 0 is the pool's protocol (subtract at wake, add at park) and adjacent worker states, as before the lane; 1 opts in to the ack-count parking and 64-byte worker states.
- GUILD_Q8_PAIR, default 1: Q8_0 rows' weight scales a block pair at a time; 0 restores the one-block build.

## gain_summary

The fix, measured on the 2x Xeon Gold 6130 + GTX 1070:
- Two busy worker cores: the default now runs Drama 3 at 41.51 frames/s against 23.14 with the acks (1.79x). That is the old protocol's speed (the verifier measured 41.61 and 40.54).
- Same load on Qwen: 34.17 / 43.33 tok/s against 19.86 / 24.24 (+72% / +79%).
- A 10%-duty task on one worker core: Drama 3 +4.7% (46.80 vs 44.70).
- Workers sleeping between frames: Drama 3 +1.0% (47.30 vs 46.83).
- Idle, the default gives up whatever the acks might gain, which is still not resolved: Drama 3 ack1 minus def was +0.29 and +1.63 frames/s here. Over all 6 idle pairs from three agents the mean is +0.32 frames/s, se 0.34 (+0.7%).
- Idle Qwen tok/s did not move (-0.04% prose, +0.37% code). Prose CPU dispatch was +0.48 ms with the default, one pair.

What the lane delivers with item 4 off (the verifier's A/Bs):
- Drama 3: the kq rows give decode +0.75% over 3 pairs with acks off in both arms, and the 86-row prompt -5%.
- Nemotron: prefill -3.7% / -3.5%, decode within noise.
- Qwen items 2+3: CPU dispatch -0.42% prose and -1.23% code (measured with acks on in both arms), tok/s within noise.
- Ornith: neutral.

## not_taken

- Dropping aa492f7 entirely: kept as an opt-in. Its profiled idle effect (-0.14 ms of pool walls a Drama 3 frame) may matter on CPU-bound PCs with free cores; nothing changes unless GUILD_POOL_ACK=1 is set.
- Rewriting aa492f7's message by rebase: the fix is a new commit on top, so the SHAs the verifier reviewed stay valid.
- Running GLM end to end now: deferred to integration (see open issues).
